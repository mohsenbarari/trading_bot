This manual workflow qualifies npm security repairs on disposable, non-root GitHub-hosted runners. It has no production SSH credentials, deployment step, or serving authority. Local candidate specifications remain unarmed; the reviewed published `spec.json` is intentionally armed only to run this CI. An armed CI specification is not security-release approval.

Dispatch requires the exact reviewed project commit, worker SHA256, and armed-specification SHA256. The worker verifies these, the exact Node24.22.1 binary, and public provenance sidecars before fetching anything. Root owns source publication, dispatch, review of results, and any separate release decision. Source fixtures or an existing artifact never replace a genuine completed CI job.

Five independent upstream jobs keep the original major contracts: glob10/11, minimatch9/10, and node-resolve15. Fork versions explicitly end in `-project.security.1`; they are not advertised as official publisher fixes. Each job fetches one exact Git commit and frozen maintainer lock, verifies Git source identities, and reproduces authenticated official runtime preimages before applying the reviewed repair. glob10 has four erased TypeScript assertions to repair an upstream type-check failure; the emitted CLI must still match the original official bin exactly. minimatch includes a bounded regression for both compiler guards. All original maintainer tests, lifecycle hooks, and coverage thresholds remain enabled. node-resolve removes only its static DEFAULTS clone's deepmerge dependency and retains the upstream license.

The original comparison runtime is stored with unchanged original metadata in an independent `.security-original-package`. A bounded no-follow inventory omits only the exact frozen tshy development link back to the live package. A newly owned internal self-reference points exclusively to the saved original package. Unknown links/types refuse for both the original and rebuilt distributions. The final fork archive explicitly refuses inclusion of the saved old runtime. Actual CJS/ESM regressions, two clean compiler outputs, and two identical npm tar bodies are required. Public stage events and bounded Source coordinates identify failures without Env, locals, or raw process arguments.

The dependent frontend job starts from the exact original634b lock and compares the original and repaired complete PWA build bytes. It allows only the declared forks and deepmerge removal; any non-target version, integrity, resolved source, or multiplicity change refuses. Two fresh frozen npmci installations, the Node guard, lint, types, and complete unit suite must pass. No build difference is silently stripped. The official npm advisory query sends only names/versions and maps private forks back to their authenticated publisher preimages, retaining the raw response. The separate narrow legacy minimatch3/5 decision applies only to the authenticated absent algorithm; raw advisory findings are not erased.

Chromium, Firefox, and WebKit jobs then install the exact produced proposal and run the repository's full browser suites against their own disposable backend fixtures. The backend bootstrap alone receives a read-only package token. Runner-local cleanup does not touch production services.

Acceptance requires all five upstream jobs, the frontend job, and all three browser jobs to finish successfully in the same immutable run, followed by independent review of provenance, graph changes, outputs, and logs. Preserved run41260493160 exposed an upstream glob10 type error, minimatch10's uncovered new branch, and a tshy self-link recursion in the comparison snapshot; those failures remain evidence. Source corrections and local tests alone do not close these failures. Any separate glibc or other security HOLD also remains independent of this workflow.
