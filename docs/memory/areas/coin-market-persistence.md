# Coin Market Persistence

- Inputs are event-driven, never synthetic per-second rows. Inference refresh=5s; XAU/USDT point is the latest real event within 90s, never forward-filled. Persist each successful 10s Wallex poll and parsed XAU quote; retain consumed 90s point/mean, invoked 180s USDT trend and 600s regime roles. One-XAU/minute compaction is not parity-safe.
- Private melted persistence has immutable offered price/quantity and no `final_price/final_quantity`. Store outcome separately as `trade_status` plus evidenced executed/remaining quantity.
- Market Facts use a dedicated durable one-way lane over the provider private network; keep its queue/checkpoints independent of general product sync while reusing authenticated integrity-checked transport primitives.
- The replacement pipeline is Docker-native: one commit-bound image, separate commands, persistent local volumes, no baked data/secrets or network-shared SQLite. Host-native legacy stays for shadow/rollback until parity passes.
- Cutover seeds facts/calibration/external history, not raw Telegram. Analyze on `65.109.220.59`; promote only after parity/freshness/magnitude/open-market live gates.
- Private-network Stage 1 passed bidirectionally with TLS 1.3, dual-key HMAC, replay/skew guards, ≥25 MiB/s, p95 <3.5 ms, zero public exposure, failure recovery and full rollback. No runtime endpoint/cutover remains active.
- Market archive uses a dedicated PostgreSQL 15 database on the web/data host; product DB/Alembic and model-side SQLite remain separate. Wire decimals are strings, DB economics are NUMERIC, UTC/availability is authoritative, and fact/outbox commit atomically.
- Permanent Telegram identities/selected raw text stay encrypted on web with HMAC lookup and audited reviewer-only decrypt; Facts carry no PII. Raw/quarantine retention=3/14d, acked outbox=7d, input ledger permanent, rollback=7 open-market days.
- Docker Stage 3 passed pinned reproducible images, non-root/read-only host profiles, isolated idempotent migration, persistent recreate/rollback and zero live authority. Secret parents are `root:root 0700`, files `root:10001 0440`; PostgreSQL only adds group 10001. Resource-mount locks guard sessions/SQLite. Non-capture roles remain fixture-only.
- Docker Stage 4 uses one SQLite FULL outbox/fsynced JSONL capture per account, exact 3d availability retention, bounded 30m channel/6h group reconciliation, 2h reply ancestors, per-source health and parser-independent flow. Live needs a release-bound session marker.
- Account 2 cutover reuses its sender HMAC key; rotation would split near-cutover reply identity. Host/container session overlap is forbidden.
