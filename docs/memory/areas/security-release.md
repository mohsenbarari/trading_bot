# Security release decisions

- Main remains the release/recipe authority. Market security builds select an
  explicit immutable Git business component, preserving the accepted complete
  per-role file inventory; release commit/tree and business commit/tree are
  distinct, truthfully bound identities. Never activate unaccepted Main business
  changes, use a moving ref/Main fallback, transplant image layers, or repoint
  historical profile/COW producers. Component locks stay unarmed until actual
  product Git identities and exact manifests are verified/published.
- The new evidence-aware vulnerability assessment preserves original raw reports
  and failed gates. Only source-proven `fixed` or same-image
  `component_not_present` may resolve an exactly enumerated finding. Require
  current payload hashes, authentic package/build/source receipts, actual fresh
  probes and a decision no older than24h. Unknown, duplicate, extra, missing or
  mismatched rows/proofs, unresolved ACL callers and failed compatibility or
  cleanup block acceptance. No accepted-risk, inactivity or unreachable waiver.
  Zero unresolved findings never grants deployment/global security by itself.
- Market's true new release stamp must equal its authenticated image revision;
  a fresh role contract may change only that public stamp and admitted image
  provenance. Preserve all other business values in trusted normal RAM and
  retain the exact active two-empty-field replay pause. No private diagnostic
  Env/hash output, old replay rearming or old image-only/profile admission.
- F79's accepted93-file hybrid is an initial component only. Other roles need
  their own verified effective source; never migrate them implicitly to F79.
  Library compatibility, model behavior, real backup/new-old restore and normal
  role/runtime gates remain mandatory.
- Backup inventory admits only exact Root-approved restart drift from a fresh
  complete-role audit. Normal parity remains false; every other check and
  current CAS stay strict. Historical PID/StartedAt are constraints, not current
  proof. This grants no stop, restore, release or security authority.
- Host-library maintenance fences the complete service/timer activation graph,
  including inactive periodic consumers and watchdogs. Pause exact timers,
  await successful natural job completion, then restart only admitted daemons.
  Failed jobs refuse without reset or waiver; retain old-inode/rollback proofs.
- Use disposable CI with unchanged vendor suites and measured capacity beyond
  production reserve. GNU inotify tests require proven native filesystems;
  OverlayFS may poll. Never skip tests to fit storage.
- Compiler and image installs share exact dpkg leaf includes and full-payload
  checks. Derive runtime imports from authenticated callsites, separately from
  configure capabilities. Retain all caller observations before semantic ABI
  gates; no absence waiver or global policy change.
- Transport parcels/binaries use separate explicit bounded writers; preserve
  receipt limits. Retain exported files through all outer physical finalizers.
- Named-context builds use a dedicated fixed recipe; preserve ordinary callers.
  Finish mutable cache checks before immutable timestamp/context admission.
- Read optional Docker fields through index. Preserve bounded build-log prefix
  and tail. Normalize only the two proven Root-owned man directories; never
  weaken generic parent admission.
