# AE03-C5e: گام اتصال محافظه‌کارانهٔ تأیید نهایی سهمیه

این تغییر فقط یک مسیر اختیاری به `run_cycle` می‌افزاید و به‌تنهایی چرخهٔ زنده را فعال نمی‌کند. در مسیر عادی، پارامتر `quota_original_controller_run_id` برابر `None` است و رفتار پیشین حفظ می‌شود.

اگر در آینده مسیر ادامهٔ سهمیه شناسهٔ معتبر اجرا را به‌صورت صریح بدهد، چرخه پس از اعتبارسنجی نتیجهٔ Codex و فقط برای `CONTINUE` یا `COMPLETE`، پاک‌بودن مخزن و ثبات رفرنس‌های محافظت‌شده و محدودهٔ Assignment را دوباره کنترل می‌کند. سپس در همان قفل Supervisor، سابقهٔ پذیرش و تأیید نهایی را منتشر می‌کند؛ این کار پیش از checkpoint و وضعیت نهایی انجام می‌شود. وضعیت اولیهٔ `RUNNING` پیش‌تر ثبت می‌شود و نباید با وضعیت نهایی اشتباه گرفته شود.

اگر تأیید نهایی یا کنترل‌های پیش از آن خطا بدهد، خطا به `QuotaFinalizationHardStopError` تبدیل می‌شود و `run_loop` با `BLOCKED` و `ambiguous_change=True` بدون تلاش مجدد خارج می‌شود. `KeyboardInterrupt` و `SystemExit` همچنان مستقیماً عبور می‌کنند. شناسهٔ نامعتبر پیش از دسترسی به مخزن یا ساخت run رد می‌شود و متن آن در خطا افشا نمی‌شود.

آزمون ایزولهٔ پیشنهاد Gemini: ۲۰/۲۰؛ بازبین مستقل Gemini: `VERIFIED`؛ آزمون نهایی Codex برای این مسیر و فایل‌های مرتبط: ۸۱/۸۱. پیشنهاد آزمون با SHA-256 برابر `f5861678f81c2c6b0eedcaceefc634285b8910e2910087bf464987e9fed06927` پذیرفته شد.

مرزهای باز: این تغییر هنوز هیچ CLI flag، wake، replay یا اتصال زندهٔ Broker/Monitor را فعال نمی‌کند. خرابیِ نوشتن وضعیت، راه‌اندازی مجدد از وضعیت کهنه، مسابقهٔ STOP، ماتریس خطا و سیاست نگهداری همچنان باید جداگانه اثبات شوند. اجرای قدیمی یا سهمیه‌خورده نباید با تکیه بر این تغییر دوباره پخش شود. `main`، محیط تولید، DNS و Web Writer خارج از دامنه‌اند.
