This source packet is an ordinary isolated restore, not serving activation. It does not use the old C/S/R/COW package, a source overlay, a source bind, a diagnostic App profile, or replacement App environment values. The standalone producer is `deploy/maintenance/normal_app_restore_producer.py`; the strict sequence is `normal_app_restore_rehearsal.py`. Its factory remains unarmed until Root supplies fresh, exact public bindings and normal backup inputs. No protected backup, Env or TLS payload was read during implementation.

## Installed DNS source witness

The current supported engine is 29.9.2, GitCommit 0367cbeb49b9d98cb0b4f51e95f7b54b4803e76c (normal API may report its 7-character prefix). The official [release](https://github.com/moby/moby/releases/tag/docker-v29.9.2) binds that commit to docker-v29.9.2. These are source facts, not an actual kernel/daemon observation made by this packet's author:

- [sandbox_dns_unix.go209–228](https://github.com/moby/moby/blob/docker-v29.9.2/daemon/libnetwork/sandbox_dns_unix.go#L209-L228) applies explicit DNS overrides.
- [resolvconf.go235–252](https://github.com/moby/moby/blob/docker-v29.9.2/daemon/libnetwork/internal/resolvconf/resolvconf.go#L235-L252) marks override servers as container-namespace servers and places127.0.0.11 in generated resolver configuration.
- [resolver.go450–466](https://github.com/moby/moby/blob/docker-v29.9.2/daemon/libnetwork/resolver.go#L450-L466) uses the backend namespace for those upstream connections. Thus an explicit127.0.0.1 upstream remains container-local.
- [sandbox.go509–521](https://github.com/moby/moby/blob/docker-v29.9.2/daemon/libnetwork/sandbox.go#L509-L521) ignores internal endpoints when deciding external access. This alone is insufficient: the resolver can still contact an on-network/container-namespace upstream. Exact explicit loopback DNS, single internal attachment and kernel readback remain mandatory.

The active checker reports only reserved-name nonresolution and fixed TCP witnesses. NXDOMAIN for a reserved name cannot establish absence of DNS forwarding. The public isolation-support receipt must bind this reviewed installed-source basis; unsupported engine provenance refuses before any App starts. No production resolver/config/Env was inspected in preparing this witness.

Docker29.9.2 [Mount.ReadOnly](https://github.com/moby/moby/blob/docker-v29.9.2/api/types/mount/mount.go#L24-L37) serializes false with `omitempty`. Only this absent-versus-false default is modeled in typed private comparison copies; raw HostConfig is retained, true/false remain distinct, and unknown mount options or nonboolean values refuse.
