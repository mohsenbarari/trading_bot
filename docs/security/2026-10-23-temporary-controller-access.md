# Temporary Web → Bot maintenance controller access

This is an explicitly temporary **root command capability**, not a new permanent
access system. `restrict` disables forwarding, agent forwarding, PTY and related
features; it does **not** sandbox the remote shell or restrict root commands.
Only the existing Web host `65.109.220.59` may use the key on native Bot
`65.109.216.187:22`, and sshd expires it at **2026-10-24 01:30 UTC**. No third host,
password setting, sshd configuration/reload, application, Writer or DNS changes.

The native Bot controller must already have strict, trusted SSH access to Web
`65.109.220.59:37067`. The reverse pin is derived from Bot's native public
`/etc/ssh/ssh_host_ed25519_key.pub`; no TOFU or `ssh-keyscan`. Both machines must
be root-owned native systemd hosts with the expected public interface address,
safe `/root` and `/root/.ssh` parents, and Bot must already have a regular,
root-owned, single-link `authorized_keys`. The playbook does not create it.
No concurrent root/automation editor of `authorized_keys` may run during this
short operation: standard `lineinfile` is atomic but is not a concurrent-editor
compare-and-swap protocol. Existing key lines, owner and mode are preserved;
appending may normalize a missing final newline.

## Reviewed invocation (not executed as part of source tests)

Run from the reviewed checkout **on native Bot**, using the separate public
inventory, not the Docker daemon inventory. Use one fresh, remembered lowercase
task id. The default command only inspects public host keys and safe metadata;
it creates no managed directory/key/pin/authorized line:

```sh
ansible-playbook -i deploy/maintenance/controller_inventory.example.yml deploy/maintenance/controller_access.yml -e controller_access_id=security-maintenance
```

After final source/operational review, setup requires both explicit action and
the exact dated confirmation; neither confirmation nor id contains credentials:

```sh
ansible-playbook -i deploy/maintenance/controller_inventory.example.yml deploy/maintenance/controller_access.yml -e controller_access_id=security-maintenance -e controller_access_action=setup -e controller_access_confirmation=TEMPORARY-ROOT-SSH-20261024T013000Z
```

The Web-only private key lives at
`/root/.ssh/security-controller-20261023-security-maintenance/id_ed25519` inside
0700 root-owned storage. It is generated by Web's `ssh-keygen` and used locally
by Web's SSH client. It is never slurped, read, hashed or returned by Ansible;
metadata inspection explicitly disables checksum and MIME detection. Only its
validated public half and the trusted public host pin cross the control channel.
The setup's final strict SSH `/usr/bin/true` probe also proves the actual Web
source satisfies Bot's `from=` restriction. A failed probe is a failure, not a
claim that external reboot control is ready; revoke/clean up with the same id.

Cleanup is explicit and remains available after expiry. Revoke the exact owned
authorized-key line **before** removing the Web-only key/pin/public files:

```sh
ansible-playbook -i deploy/maintenance/controller_inventory.example.yml deploy/maintenance/controller_access.yml -e controller_access_id=security-maintenance -e controller_access_action=cleanup -e controller_access_confirmation=TEMPORARY-ROOT-SSH-20261024T013000Z
```

Cleanup preserves unrelated authorized lines and rejects changed public ownership
proofs, changed pins, unknown workspace entries, symlinks or hardlinks. It removes
individual owned files, public ownership proof last, then uses `rmdir` on the
empty task directory (never recursive deletion). Repeating cleanup of an already
absent workspace is allowed only if no matching managed key remains. If key
generation crashes before producing its `.pub`, fail closed and inspect the
specific task directory manually; do not invent a public proof or delete broad
paths. Expiry denies authentication but **does not delete private files**: always
perform cleanup. Ansible `--check` also stops before every managed write.

## Evidence boundary

Hermetic tests parse and check the playbook, validate synthetic public keys and
filesystem failure cases, and never execute SSH, Ansible setup, host probes or
real credential reads. A syntax check is not successful host execution. Actual
setup, expiry support, strict round-trip and cleanup must be recorded separately
by the operator before using Web as an external reboot controller.
