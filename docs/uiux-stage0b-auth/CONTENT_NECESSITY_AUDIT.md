# Stage 0B-1 content-necessity audit

تاریخ: ۲۰۲۶-۰۸-۰۸

دامنه: ۱۵ قاب محصول موبایل، چهار illustration کیبورد و proof دسکتاپ در `auth-scenarios.html`

قاعده: هر واحد محتوای همیشه‌نمایان باید کار جاری، تصمیم، وضعیت ضروری یا پیشگیری از پیامد مهم را پشتیبانی کند. scenario labelها، codeها، state atlas و annotationهای بیرون `.phone` اسناد بازبینی‌اند و UI محصول محسوب نمی‌شوند.

## واحدهای مشترک

| واحد | تصمیم | دلیل |
| --- | --- | --- |
| brand کوچک در header | `Keep` | هویت و اعتماد در flow عمومی حساس؛ فقط یک‌بار و بدون chip زمینه تکراری |
| `surface-chip` همه قاب‌ها | `Remove` | عنوان/وضعیت هر قاب همان context را روشن می‌کند |
| footer ثابت همه قاب‌ها | `Remove` | در نمونه قبلی اغلب قرارداد داخلی یا تکرار body بود؛ safety copy لازم به context اصلی منتقل شد |
| progress واقعی ورود/ثبت‌نام | `Keep` | موقعیت کاربر و Back را تعیین می‌کند |
| deadline/countdown مؤثر | `Keep` | فوریت و امکان ادامه را تغییر می‌دهد |
| privacy/security/error copy | `Keep` و نزدیک field/action | از پیامد مهم جلوگیری می‌کند؛ خلوتی مجوز حذف آن نیست |
| انتخاب واقعی وب/تلگرام | `Keep` | خود تصمیم کاربر است، نه metadata مسیر |

## کیبورد و دسکتاپ

- illustrationهای کیبورد فقط field، context کوتاه و CTA لازم را نگه می‌دارند؛ عبارت implementation «کنترل واحد» از قاب OTP حذف شد.
- proof دسکتاپ همان اطلاعات موبایل ارسال مدرک را نگه می‌دارد: deadline، انتخاب فایل، فایل انتخاب‌شده، توضیح، پیامد حریم خصوصی و actionها.
- ستون توضیحی، progress چهارمرحله‌ای، metadata header و توضیح استفاده از فضای اضافه حذف شدند. فضای خالی با اطلاعات جدید پر نشد.

## موارد منتقل‌شده به state مربوط

- خطای ساخت لینک تلگرام فقط در state خطای اتصال نمایش داده می‌شود، نه قاب normal؛
- خطای API و حفظ ورودی در state atlas/پیاده‌سازی آزموده می‌شود، نه به‌عنوان notice دائمی؛
- پیشنهاد نصب PWA به تصمیم Stage 0B-2 پس از ورود منتقل شده است.

واحد محتوای همیشه‌نمایان بدون پرسش یا اثر ثبت‌شده پس از این اصلاح: `0`.

این audit قضاوت محتوایی است. fit، contrast، touch target و screenshot metrics شواهد جداگانه‌اند و جای آن را نمی‌گیرند.
