# Stage 0B-3 content-necessity audit

اصل مرجع: هر واحد همیشه‌نمایان باید اقدام، تصمیم، وضعیت ضروری یا پیشگیری از ریسک را ممکن کند. اگر حذف یک واحد، معنا و توان انجام کار را کم نکند، همان واحد شکست ممیزی است.

## ممیزی قاب‌های اصلی

| قاب | پرسش کاربر | Keep | On demand | Remove از نمای پیش‌فرض |
| --- | --- | --- | --- | --- |
| `M01` عملیات مالک | کدام کار عملیاتی را اکنون می‌توانم آغاز کنم؟ | عنوان و فقط مقصدهای واقعی مشتری/حسابدار | توضیح هر workspace پس از ورود | تعداد مسیر/ابزار، نقش، summary دسترسی و کارت تزئینی |
| `M02` عملیات مدیر ارشد | کدام مقصدها برای من قابل استفاده‌اند؟ | مقصدهای مجاز و navigation | metadata مدیریتی در نقطه تصمیم مرتبط | شمارنده، role chip، جمله «بر اساس دسترسی» و destination غیرفعال |
| `M03` حسابدار بدون اقدام | اگر اینجا کاری ندارم از کجا ادامه دهم؟ | empty کوتاه و یک راه معتبر به حساب | راهنمای نقش در کمک/پشتیبانی | destinationهای مالک، CTA مرده و توضیح permission/API |
| `M04` فهرست مشتری | چگونه رابطه را پیدا یا اضافه کنم؟ | جست‌وجو، افزودن، صف دعوت اقدام‌پذیر و ردیف‌های رابطه | تاریخچه و جزئیات پس از انتخاب | تعداد کل روابط، summary کارت‌محور و metadata تکراری هر ردیف |
| `M05` دعوت در انتظار | چه زمانی منقضی می‌شود و چه اقدامی لازم است؟ | نام، مهلت یک‌بار، failure ارسال، copy وب/تلگرام و cancel جدا | تاریخچه تلاش‌های ارسال | تکرار deadline، توضیح مسیر، count بی‌اقدام و CTAهای هم‌وزن خطر/عادی |
| `M06` ویرایش مالی | چه چیزی عوض می‌شود و اثر آن چیست؟ | فیلدهای لازم، before/after، future-only و مرور نهایی | تاریخچه تغییرات و جزئیات محاسبات | اطلاعات تکمیل‌شده تکراری، KPI، متن سیاست طولانی و ذخیره بدون review |
| `M07` فهرست حسابدار | چگونه حسابدار را پیدا یا دعوت کنم؟ | جست‌وجو، افزودن، صف pending و یک disambiguator لازم | جزئیات رابطه پس از انتخاب | تعداد کل، چند شناسه هم‌زمان، شرح وظیفه کامل و نقش تکراری |
| `M08` شرح وظیفه | چه متنی را ویرایش و چگونه ذخیره کنم؟ | هویت، یک textarea، ذخیره و feedback همان‌جا | تاریخچه نسخه‌ها | کپی جداگانه «شرح فعلی»، metadata رابطه و success card دائمی |
| `M09` پایان نشست | کدام دستگاه خارج می‌شود و پیامد چیست؟ | دستگاه/پلتفرم، آخرین فعالیت لازم، جاری/اصلی در صورت اثر، confirm و feedback | جزئیات امنیتی بیشتر | `home_server`، نام سرور، API، IP بی‌اثر و چند نشان وضعیت هم‌معنا |
| `M10` حذف حساب | دقیقاً چه چیزی حذف یا غیرفعال می‌شود؟ | نام شخص، cascade کامل، تأیید قوی، cancel و CTA خطرناک دقیق | audit log پس از اقدام | واژه کم‌خطر unlink، توضیح مبهم، KPI و پنهان‌کردن پیامدها به نام خلوتی |

## ممیزی state atlas

| state | Keep | Remove |
| --- | --- | --- |
| Loading | skeleton متناسب با ساختار و shell پایدار | هویت، count، status یا permission فرضی |
| Load error | پیام cause-neutral و retry نزدیک | empty دروغین، blame قطعی شبکه و جزئیات backend |
| True empty | تفاوت روشن «هنوز رابطه‌ای نیست» و افزودن در صورت مجازبودن | عدد صفر، کارت آماری یا جست‌وجوی بی‌معنی |
| Search empty | query فعلی و پاک‌کردن جست‌وجو | پیام true-empty یا پیشنهاد ساخت رابطه نامرتبط |
| Missing detail | عدم وجود/دسترسی و بازگشت معتبر به فهرست | spinner نامحدود، route و شناسه فنی |

## ممیزی desktop master/detail

فضای دسکتاپ برای دیدن هم‌زمان فهرست و جزئیات همان task استفاده می‌شود. موارد زیر مجاز نیستند:

- KPI تعداد روابط یا دعوت‌ها صرفاً برای پرکردن header؛
- sidebar یا navigation architecture تازه؛
- metadataای که در موبایل برای تصمیم لازم نبود؛
- summary انتخاب که بلافاصله در عنوان و جزئیات تکرار می‌شود؛
- نمایش هم‌زمان چند پرونده یا چند اقدام حساس.

## تصمیم‌های سراسری

### Keep

- هویت لازم برای جلوگیری از اقدام روی فرد اشتباه؛
- جست‌وجو و اقدام اصلی واقعی؛
- وضعیت رابطه فقط وقتی اقدام را تغییر می‌دهد؛
- صف pending و شمارنده آن فقط چون نیازمند رسیدگی است؛
- اثر future-only تغییر مالی؛
- پیامد کامل اقدام امنیتی یا حذف حساب؛
- feedback در همان context اقدام.

### On demand

- تاریخچه دعوت، ویرایش، نشست و رابطه؛
- جزئیات حسابرسی و شناسه‌های پشتیبانی؛
- metadata تکمیلی نشست؛
- اقدام‌های کم‌تکرار و خطرناک پس از ورود به جزئیات؛
- شرح وظیفه کامل حسابدار پس از انتخاب او.

### Remove

- تعداد کل مشتریان، حسابداران، مسیرها و ابزارها؛
- role chip و summary دسترسی؛
- route، API، backend، server و `home_server`؛
- destinationهای مرده برای حسابدار؛
- تکرار نام، وضعیت، deadline یا شرح وظیفه در یک viewport؛
- card، badge، divider، icon یا helper صرفاً برای پرکردن فضای خالی.

## نتیجه

ممیزی ۱۰ قاب موبایل، state atlas، پنج proof responsive و proof دسکتاپ پاس است: هر واحد پیش‌فرض یک اثر روشن بر task، تصمیم، وضعیت یا ریسک دارد؛ شمارنده فقط برای صف pending اقدام‌پذیر باقی مانده؛ اطلاعات زیرساختی حذف شده؛ و پیامدهای حذف حساب به نام خلوتی پنهان نشده‌اند. بازار و پیام‌رسان فقط مقصد shell هستند و هیچ interior تازه‌ای برای آن‌ها تعریف نشده است.
